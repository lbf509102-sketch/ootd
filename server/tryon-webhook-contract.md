# Try-On Webhook Contract

This project supports two try-on generation providers:

- `mock`
- `webhook`

Use `webhook` when you want the app to call an external try-on service such as an IDM-VTON style backend.

## Environment variables

Set these values in `.env`:

```env
TRYON_PROVIDER=webhook
TRYON_WEBHOOK_URL=http://your-service.example.com/try-on
TRYON_WEBHOOK_TOKEN=
TRYON_FALLBACK_TO_MOCK=true
```

Notes:

- `TRYON_WEBHOOK_TOKEN` is optional. If present, the app sends it as `Authorization: Bearer <token>`.
- If `TRYON_FALLBACK_TO_MOCK=true`, webhook failures automatically fall back to the built-in mock renderer.

## Request payload

The app sends a `POST` request with JSON:

```json
{
  "sessionId": "tryon-123",
  "phone": "13800138000",
  "personImageUrl": "/uploads/person.webp",
  "garmentImageUrl": "/uploads/garment.webp",
  "garmentName": "奶油白短袖衬衫"
}
```

Field meanings:

- `sessionId`: local try-on task id
- `phone`: current user phone
- `personImageUrl`: uploaded reference photo path on this server
- `garmentImageUrl`: uploaded garment image path on this server
- `garmentName`: display name for the selected garment

## Response contract

Your webhook must return one of these:

### Option A: return a final URL

```json
{
  "resultImageUrl": "https://cdn.example.com/tryon/output-123.webp",
  "note": "IDM-VTON result generated successfully."
}
```

### Option B: return an image data URL

```json
{
  "dataUrl": "data:image/png;base64,...",
  "note": "Generated by remote try-on service."
}
```

If `dataUrl` is returned, this app automatically stores it under local `/uploads/...` and converts it into `resultImageUrl`.

## Error handling

Recommended behavior:

- Return non-2xx for hard failures.
- Include a short plain JSON message when possible.

Example:

```json
{
  "message": "Garment mask was missing."
}
```

If the webhook fails and `TRYON_FALLBACK_TO_MOCK=true`, the app writes a completed task using a mock preview instead of leaving the user with no result.

## Local testing

This repo includes a sample local webhook endpoint:

```text
POST /api/dev/try-on/webhook-sample
```

You can test the webhook path end to end with:

```env
TRYON_PROVIDER=webhook
TRYON_WEBHOOK_URL=http://127.0.0.1:3001/api/dev/try-on/webhook-sample
TRYON_FALLBACK_TO_MOCK=true
```

That sample endpoint returns a mock-generated preview through the webhook path, which is useful for validating your task flow before you connect a real service.
